# 🎟️ Concert Ticket Booking System

Высоконагруженный backend-сервис для бронирования и выкупа концертных билетов с защитой от гонок (race conditions), гарантированной доставкой событий и идемпотентной обработкой платежей.

Проект спроектирован с упором на надёжность данных при высокой конкурентности (когда сотни пользователей одновременно пытаются выкупить один и тот же билет).

---

## 🛠️ Технологический стек

* **Язык и фреймворк:** Java 21, Spring Boot 3.4.5
* **База данных и миграции:** PostgreSQL 16, Spring Data JPA, Flyway
* **Кэш и распределённая синхронизация:** Redis 7 (Spring Data Redis)
* **Безопасность:** Spring Security, Stateless JWT (`JJWT 0.12.6`)
* **Документация API:** OpenAPI 3 / Swagger UI (`springdoc-openapi 2.8.6`) с поддержкой JWT Bearer
* **Тестирование:** JUnit 5, Mockito, AssertJ, MockMvc, Testcontainers (PostgreSQL + Redis)
* **Инфраструктура:** Docker (multi-stage build), Docker Compose с `healthcheck`

## 🏗️ Ключевые архитектурные решения

### 1. Защита от двойного бронирования (Concurrency Control)
* **Пессимистичные блокировки (`PESSIMISTIC_WRITE`):** при попытке забронировать или оплатить билет строка в БД блокируется (`SELECT ... FOR UPDATE`) с таймаутом `3000 мс`, исключая состояние гонки при одновременных запросах.
* **Ленивая очистка (Lazy Expiration):** если срок предыдущей брони истёк, но фоновый воркер ещё не успел её снять, метод `reserveTicket` автоматически освобождает билет прямо в момент нового запроса.

### 2. Фоновые планировщики без конфликтов инстансов
* **`FOR UPDATE SKIP LOCKED`:** фоновые задачи (очистка просроченных броней и отправка событий из Outbox) выбирают строки с блокировкой пропуска занятых записей. Это позволяет безопасно масштабировать приложение в несколько реплик без дублирования обработки.

### 3. Идемпотентность платежей на базе Redis
* Оплата защищена заголовком `Idempotency-Key` и атомарной операцией Redis `SETNX` (`setIfAbsent`) со статусами `IN_PROGRESS` и `COMPLETED`.
* При повторной отправке запроса с тем же ключом (например, из-за сетевого сбоя или двойного клика) система не списывает средства повторно и корректно обрабатывает конкурентный запрос.

### 4. Гарантированная доставка событий (Transactional Outbox)
* При успешной оплате билета смена статуса на `SOLD` и запись события `CONCERT_TICKET_PURCHASED` в таблицу `outbox_events` происходят **в одной локальной транзакции БД**.
* Фоновый **Outbox Relay** вычитывает необработанные события и гарантирует их доставку во внешние системы (паттерн *At-Least-Once delivery*).

### 5. Stateless-аутентификация и оптимизация запросов
* Кастомный `JwtAuthenticationFilter` валидирует токен и помещает в `SecurityContext` компактный объект `AuthenticatedUser(Long userId, String username)` без лишних походов в БД на каждый запрос.
* Для чтения списка билетов пользователя (`GET /api/tickets/my`) используется `@Transactional(readOnly = true)` и `@EntityGraph`, что устраняет проблему `N+1` запросов.

## 📡 Основные API-эндпоинты

| Метод | Эндпоинт | Доступ | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/register` | Публичный | Регистрация нового пользователя |
| `POST` | `/api/auth/login` | Публичный | Аутентификация и получение JWT-токена |
| `POST` | `/api/tickets/{id}/reserve` | JWT | Временное бронирование билета (`RESERVED`) |
| `POST` | `/api/tickets/{id}/pay` | JWT | Оплата брони (`SOLD`) с поддержкой `Idempotency-Key` |
| `GET` | `/api/tickets/my` | JWT | Получение списка всех билетов текущего пользователя |

## 🚀 Быстрый старт (Docker Compose)

Для запуска всего окружения (приложение + PostgreSQL 16 + Redis 7) достаточно установленного Docker:

```bash
# 1. Клонировать репозиторий
git clone https://github.com
cd concert-ticket-booking

# 2. Собрать и запустить контейнеры
docker-compose up --build -d
```

После запуска сервисы будут доступны по адресам:
* **API приложения:** `http://localhost:8080`
* **Swagger UI (интерактивная документация):** `http://localhost:8080/swagger-ui.html`

> **Как протестировать в Swagger UI:** выполните запрос `/api/auth/register` или `/api/auth/login`, скопируйте полученный JWT-токен, нажмите кнопку **Authorize** в правом верхнем углу Swagger UI и вставьте токен.
